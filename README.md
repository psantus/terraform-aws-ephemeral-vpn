# Ephemeral AWS Client VPN with a fixed egress IP

A cheap, on-demand VPN that gives you a **fixed public egress IP** (a NAT gateway's
Elastic IP) — useful when a third-party service whitelists your IP. It's
**$0 when idle**, secured with **company SSO** (IAM Identity Center via Cognito),
and toggled from a small web page. No servers to patch: it uses **AWS Client VPN**.

## What you get

- **Fixed egress IP** — client traffic exits through a VPC NAT gateway, so
  everything appears to come from that NAT's Elastic IP.
- **Ephemeral / cheap** — the Client VPN endpoint exists always (free), but the
  billable **subnet association** is created on demand and auto-removed after an
  idle hour. You pay ~$0.10/hr only while actually in use.
- **SSO login** — users sign in with IAM Identity Center (federated through a
  Cognito user pool). No shared secrets, no per-user certificates.
- **Self-service portal** — users download their VPN profile from the AWS
  Client VPN self-service portal after SSO login.
- **One-click web UI** — CloudFront + S3 SPA: sign in, Start/Stop, live status
  with a progress bar, and a link to the portal.
- **No cert wrangling** — the Client VPN server certificate is auto-generated by
  Terraform (self-signed via the `tls` provider, imported to ACM). No local
  private key, no openssl, no manual import.

## Architecture

![Architecture](docs/architecture.drawio) — editable diagram in `docs/architecture.drawio` (diagrams.net).


```
Browser SPA (CloudFront + S3)
  │  Cognito Hosted UI (Authorization Code + PKCE)
  │    └── federated via SAML to IAM Identity Center
  │  → Cognito JWT
  ▼
API Gateway (HTTP API) ── Cognito JWT authorizer ── GET/POST /vpn
  ▼
Toggle Lambda (in-VPC, in the target subnet)
  • on     → associate subnet + add 0.0.0.0/0 endpoint route
  • off    → disassociate (AWS auto-removes routes)
  • status → associated ONLY when subnet associated AND route active;
             self-discovers the egress IP via checkip (same NAT)
  ▼
AWS Client VPN endpoint (SAML federated auth + self-service portal)
  └── associated to a private subnet → egress via NAT → fixed EIP

EventBridge (hourly) → idle-check Lambda → disassociate if idle a full hour
```

## Prerequisites (one-time, mostly console)

Client VPN + IAM Identity Center integration requires some console steps that
Terraform can't fully express. See `SETUP.md` and `FEDERATED.md` for the exact
click-by-click. In short:

1. **Three IAM Identity Center custom SAML apps.** ACS URL, audience, and
   **attribute mappings** are all fixed/required. **The attribute mappings are
   mandatory** — a missing/incorrect mapping causes the sign-in error
   "Resource not found / confirm your primary email address is assigned".

   | App | ACS URL | Audience | Required attribute mappings |
   |-----|---------|----------|------------------------------|
   | VPN client | `http://127.0.0.1:35001` | `urn:amazon:webservices:clientvpn` | **Subject** = `${user:email}` (emailAddress) + **FirstName** = `${user:givenName}` + **LastName** = `${user:familyName}` |
   | Self-service portal | `https://self-service.clientvpn.amazonaws.com/api/auth/sso/saml` | `urn:amazon:webservices:clientvpn` | **Subject** = `${user:email}` (emailAddress) + **FirstName** = `${user:givenName}` + **LastName** = `${user:familyName}` |
   | Cognito | `https://<prefix>.auth.<region>.amazoncognito.com/saml2/idpresponse` | `urn:amazon:cognito:sp:<user-pool-id>` | **Subject** = `${user:email}` (emailAddress) + attribute **`email`** = `${user:email}` |

   Notes:
   - AWS Client VPN requires **at least one attribute** in the SAML assertion
     beyond the NameID — so the client and portal apps need `FirstName`/`LastName`
     (or any attribute), not just `Subject`. Omitting them causes sign-in failures.
   - The **`email`** attribute (name literally `email`) on the **Cognito** app is
     what Cognito reads to populate the user's email — without it, federation fails.
   - **Assign your users/groups** to all three apps.
   - Download each app's metadata XML and pass the paths to the module
     (`client_saml_metadata_file`, `portal_saml_metadata_file`,
     `cognito_saml_metadata_file`).
2. **A VPC with a NAT gateway** and a private subnet that routes `0.0.0.0/0`
   through it. (Works with a RAM-shared VPC — the NAT can live in another account.)

## Deploy

```bash
cd terraform
cp example.tfvars terraform.tfvars   # fill in region, vpc_id, subnet, cert ARN
export AWS_PROFILE=<your-profile>
terraform init
terraform apply
```

One apply: create all three IDC SAML apps first (the Cognito app with a
**placeholder** audience — its ACS URL is known from your `cognito_domain_prefix`),
drop the metadata files, `terraform apply`, then update the Cognito app's ACS URL
and audience from the `cognito_saml_*` outputs. No re-apply needed. See
`FEDERATED.md`.

## The gotchas (things that cost us hours)

- **Public Lambda Function URL returned 403** despite a correct policy — it needs
  BOTH `lambda:InvokeFunctionUrl` AND `lambda:InvokeFunction` for `*`. (We later
  replaced the Function URL with API Gateway + Cognito anyway.)
- **IAM Identity Center custom SAML apps take only ONE ACS URL** — so the VPN
  client and the self-service portal need **two separate SAML apps**, registered
  as **two IAM SAML providers** on the endpoint (`saml_provider_arn` +
  `self_service_saml_provider_arn`).
- **Missing SAML attribute mapping** → "Resource not found / confirm your primary
  email". All apps need `Subject = ${user:email}`; client/portal also need at
  least one attribute (`FirstName`/`LastName`) since Client VPN requires >=1
  attribute beyond NameID; the Cognito app needs an `email` attribute.
- **VPN connected but DNS/curl hung** — the shared VPC had **DNS64** enabled, so
  the resolver returned NAT64 IPv6 the IPv4-only tunnel couldn't route. Fix: push
  public IPv4 resolvers (`dns_servers`).
- **Authorization ≠ routing** — a `0.0.0.0/0` **authorization rule** is not enough
  for internet egress; the endpoint also needs a `0.0.0.0/0` **route** to the
  associated subnet. The toggle Lambda adds it on associate (AWS removes it on
  disassociate).
- **CORS preflight 401** — an `ANY /vpn` route applied the JWT authorizer to the
  OPTIONS preflight (which carries no Authorization header). Split into explicit
  `GET`/`POST` routes so API Gateway answers preflight unauthenticated.
- **IPv6 does not traverse this tunnel** (IPv4-only endpoint) — which is fine, and
  correct, for a single fixed-IPv4-egress use case.

## Cost

- Idle: **$0** (endpoint exists, no association).
- In use: ~**$0.10/hr** per association + ~**$0.05/hr** per connected user
  (region-dependent) + minimal Lambda/API/CloudFront.
